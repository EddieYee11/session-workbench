# Com! 1.7.0 · 连续交办与状态卡

2026-10-03。基于 1.6.1 / `13b9b68`，整合 Muse `agent-work-card` bundle 的三个提交，保留原分支历史。目标是随时能补话、原事项持续推进、真实工作挂回原消息、交付有可检查的证据。

## 使用路径

五个底部入口继续为对话、今天、任务、工作、更多。主页交办下方显示工作过程卡；头像下方显示当前实际阶段；执行结束后显示总结卡、步骤、结论、产物与复制入口。点击后台任务进入原任务详情，返回对话定位原交办。折叠设备窄/宽布局沿原结构自适应。

今天页按待处理、今日时间轴、在途工作和账本摘要排列，全天日程折叠。任务页将台账、消息关联任务和授权建议按真实任务 ID 合并，提供待你决定、执行中、待验收、已完成与已结束筛选；执行结束不会直接归入已完成。今天的条目进入对应任务详情，返回保留来源页面和筛选。确认过的工作原消息跳回实际工作会话，未确认来源不伪造消息锚点。通知巡检移入更多，去掉对话中的重复任务抽屉。改版前调研与实际范围见 `COM_UX_RESTRUCTURE.md`。

头像区域按用户最新要求采用紧凑上下结构：保留原形象，下方白色圆角卡仅显示灰色图标和实时状态，不显示 Pi 名字；空闲时整张状态卡隐藏。状态文字向人物靠近，字体放大时头部自适应，状态卡不覆盖人物。普通分析／回复阶段不显示后台任务详情箭头；主线工具处理结束与项目任务待验收分别显示。

## 本轮行为

- 手机每条消息有独立、不可变的请求号和加密持久记录；保存后释放输入框。HTTP 回执与快照刷新分离。未尝试联网的本地队列可在恢复后发送，送达未知的消息仅核对或显式复用原请求号重试，不自动重放；互不依赖的消息可以继续发送。草稿切后台真正执行保存函数。
- 普通语音与文字按同一真实原文判断记账意图，不强制走独立记账入口。当前具体费用陈述及“记个账／记一笔／金额用途后说记账”共用判断，中文元、块、毛、分精确匹配金额。能力问句、引用、候选和否定不新增记录；金额或用途缺失时补齐参数。记账直接由主 Pi 处理，成功后回读 ID、金额与备注，拒绝后不能通过派任务绕过，旧失败语音不自动重放。
- Pi、Codex、Claude Code 统一最高操作权限。`operation_policy.py` 撤销 Com 额外加上的 read-only／workspace-write 和业务查询写入拦截；旧任务及会话权限迁移保留审计，不改变执行状态、不重放未知操作。手机移除限制权限选项。历史账务查询直接调用 `bookkeeping_search`，复用现有 ezBookkeeping 客户端按日期、金额、关键词检索，不局限最近 30 笔，也不强制委派。查询自然只查询；真实来源、金额用途、去重和严重不可逆动作检查继续保留。
- 主线消费循环隔离后台异常，并可重建结束的消费者。Pi 原生历史在真正完成事件后更新。当前事项的明确补充走原生 steer；ACK、原生 message_start、执行结束分别记录。真正送达前不更换工具的用户授权来源；独立工作保持普通消息排队。
- 工作页用户主动向 Codex／Claude Code 发送的问候、问题和讨论，作为真实工作聊天直接提交，不要求改写成明确交办句，也不在每轮回复后等待任务验收才能接着聊。所选目录和权限沿真实消息记录；最高权限工作会话直接使用所选目录，不为一句问候复制整个工作区。模型主动提出的后台任务仍需真实原文支持，普通聊天不会伪造为自动交办。
- “继续／接着做／按上面那个”和后续验收、合入沿真实用户消息与任务来源定位；歧义任务保留明确对象选择。启动前暂停可重新检查环境后恢复或取消；已执行或送达未知不重放。
- 工作器启动与发送任务分别留证。明确在发送前失败时显示原因并暂停，恢复保留旧事件并产生新的启动尝试；发送阶段失联仍保留待核实。各执行者直接在原授权目录工作，不为问候或查询复制整个工作区。
- Pi 操作工作器撤销操作沙箱只读限制。独立无工具 Judge 继续使用评估进程隔离；原生认证锁生命周期兼容仍保留，不复制凭据。明确的 prompt 启动前拒绝与传输未知分别记录，已开始或无法确认的请求不自动重放。
- 任务持久保存 source_links、source_message_ids、context_revision、当前工作说明和补充送达状态；工作器收到最新要求。旧只读标签保留历史依据，当前执行提示明确它们已撤销。任务结果回执关联真实原交办，普通工作聊天无需额外主 Pi 再评审。
- 同目标下显式 plan_node_id 可并行，depends_on 等待前置实际验收；历史写副本保留对应执行轮次合入机制。新任务直接在授权目录执行。未声明节点的旧目标保留原串行规则。维持后台两个、Claude 一个的并发额度。
- 卡片读取真实工具开始/结束事件与任务账本，事件通过同一 SSE 返回原消息。断线快照和重启保持步骤。工具没有结束证据就标待核实；执行者文字“完成”不会变成验收通过。程序验收通过但写副本尚未合入时明确显示待合入。
- task_verify 的 checks 可关联 acceptance_criteria。覆盖必须完整；多条要求或显式 quality_review 时，在程序检查后用当前 Pi/Flash 做独立无工具评审，返回 pass/revise/unknown、证据缺口与下一步。每个结果轮次最多两次，不自动无限返工，不增加新模型或修改全局认证。
