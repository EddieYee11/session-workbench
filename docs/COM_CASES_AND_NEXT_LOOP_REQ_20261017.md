# Com · 案例（交给 Com）与「下一步 / 待办」闭环 · 需求定稿

> 2026-10-17 采访 Eddie 后整理。范围：后端（mini）+ iOS。Android 本版不动。
> 状态：2026-10-17 Eddie 确认开工，并把「对照行动台去重」纳入本版。

## 0. 为什么做

- 「交给 Com」现在只是把建议的 prompt 塞进主对话（`app.py` `/personal/next/{id}` action=discuss → `conversation.submit`），没有独立任务、看不到进度。`next-steps.sqlite` 里 27 条 acted，没有一条变成可跟踪的任务。
- 主对话是 Hermes（`deepseek-v4-flash`），复杂/长任务不靠谱，Eddie 因此不敢点。
- 下一步、待办（Obsidian 行动台 `任务/待处理/`）、等你点头（审批卡）三套数据互不相通。

## 1. 案例（Case）

**定义**：一次「交给 Com」= 一个案例 = 一个独立的 Pi session，有自己的步骤时间线和对话。

| 项 | 决定 |
|---|---|
| 谁生成案例 | ① 下一步里点「交给 Com」；② 待办里点「交给 Com」；③ 对话里 Eddie 让它做复杂/长任务时，Hermes 主动开案例，对话里留一张可点进去的卡片 |
| 谁干活 | Hermes 当调度员：理解事项、写清任务说明（目标/依据/完成标准）后派给 Pi，在独立 session 执行；记账、建日程这类简单事 Hermes 自己办（不开案例） |
| Pi 模型 | 保持现状（`opencode-go/deepseek-v4.1-flash` via Magpie），本版先把流程和跟踪做出来 |
| 开工方式 | 点了就直接跑，不出计划卡 |
| 中途遇到分岔 | 自己选最稳妥的往下走，**把每个假设记下来**，跑完一起列给 Eddie |
| 唯一停点 | 不可逆删除/清空（沿用 2026-10-02 规则，闸门真源 `task_tools.py::authorized_assignment`）：案例状态变「等你」，推送，Eddie 在案例里批准/拒绝后继续 |
| 完成 | 跑完即「完成」，不需要验收；有问题 Eddie 在案例里插话，同一 session 接着改 |

**案例状态**：进行中 → 完成 / 失败；中途可能进入「等你」（仅删除审批），可被 Eddie 暂停、取消。

**案例详情页（iOS）**
- 步骤时间线：已完成 / 进行中 / 待做，加一句「现在在干什么」（Muse 式）
- 中途插话：随时补一句话、改方向、暂停、取消（写进同一个 Pi session）
- 产出汇总：结论、做了哪些假设、产出物（改动的文件、草稿、链接）
- 不做：原始 transcript 展开（本版不要求）

**入口**：下一步页右上角小入口「案例 · N 进行中」→ 案例列表（进行中在上，历史在下）→ 详情。不进一级 tab。

**通知**：完成时、等你（删除审批）时、失败/超时时推送；有案例在跑时锁屏 Live Activity 显示进度。

## 2. 下一步 → 待办 → 明天

**每条下一步的去处**（在现有「交给 Com / 已经做了 / 不用」之外新增）：
- **加到待办**：一键写入行动台 `任务/待处理/<名称>.md`（frontmatter `flow: 任务`、`状态: 待处理`、`计划结束`、`下一步`、依据与链接），日期默认明天，可选今天/后天/自选
- **加到待办并定提醒**：同上，并在指定时间走 pi-gateway 提醒
- **稍后再说**：今天不再出现，明天重新进入下一步

**明天待办建议**：每晚固定时间（默认 21:30）自动生成一张清单并推送，来源 = 未处理的下一步 + 明天到期/已过期的待办 + 明天日程 + 进行中的案例。Eddie 勾选后一键落到行动台（明天）。

**联动**
- 去重：下一步生成时对照行动台 `任务/待处理/`，已建待办的事不再作为新建议出现（命中时并入显示「已在待办 · 日期」）；由「加到待办」生成的文件记录来源 id，精确去重
- 案例完成 → 对应的下一步、待办自动标完成（待办文件改 `状态`，由 auto-move-on-property 归位）
- 待办列表（今天页）里的事项也能「交给 Com」，走同一套案例

## 7. 第二轮：四条联动（2026-10-18 凌晨，Eddie「都做」）

1. **线索关系表** `backend/threads.py` + `GET /personal/thread?key=类型:ID`：节点 next / todo / case / msg / session / project；创建处显式记录（交给 Com、加到待办、明天建议、对话派活、复杂轮次、结论回流），另从已有数据补隐式关系（下一步的 todo/case_id、案例来源、待办关联项目、案例执行会话），老数据也串得上。iOS `ThreadStrip`：案例详情、今天页待办详情顶部，点任何一环跳过去（案例开 sheet、下一步切页、对话定位消息、会话切工作页、待办/项目页开 Obsidian）。
2. **统一「等你」** `GET /personal/waiting`：等你批准的案例 + 微信在等回话（私聊或 @你、最后一条不是你；排除 Bot/提醒类账号）+ 过期待办；审批卡由客户端并入。`waitingCount` 驱动 Dock「今天」徽标、顶栏副标题、灵动岛；顶栏「等你」chip 和深链 com-eddie://waiting 打开 `WaitingSheet`（审批直接批、案例点开、微信「让 Com 起草回复」、过期待办长按改期/完成/交给 Com）。
3. **案例结论回流** `Cases.backflow`：案例结束（含没做成）时一行写进对应待办和它「关联项目」页的「## 进展」（项目页没有这段就在「## 笔记」前新建），先回流再打勾；并记一条 case→project 线索。
4. **会话↔案例互通**：`/sessions` 给执行会话带 `case_id/case_title`；工作页会话行显示「案例 · 标题」+ 长按「查看案例」，工作页聊天顶部「案例「X」的执行会话 · 看案例」；案例详情「在工作页打开执行会话」。
