# Com! iOS 升级方案（2026-10-09，Claude 接手）

> 对标：**Hark Pro**（2026-10-06 发布的主动式个人 AI，读邮件/日历后用「一张卡一个动作」的方式找你）和 **Meta Muse**（一条持续对话、界面极简）。
> 来源：Codex 会话回溯（9-28～10-09）、docs/ 19 份文档、ios/ 源码审计、mini 上的运行数据（hermes-runs / personal-hub / notifications / Magpie usage）。

## 一句话结论

Com! 现在「不顺畅」不是动效问题，是三件事：**一句话等一分钟**、**七天没主动说过一句话**、**App 切出去再回来要重连一整套**。Hark Pro 的主动性和 Muse 的简洁都建立在「快 + 真的有事找你」之上，先把这两件事做成，再谈界面。

## 1. 实测现状（不是文档口径）

### 1.1 对话延迟（mini `hermes-runs.sqlite`，最近 33 次真实对话）

| 指标 | 实测 | 文档声称 |
|---|---|---|
| 首字延迟中位数 | 78 s | 2.4～3 s |
| 首字 > 10 s 的比例 | 82% | — |
| 首字 > 30 s 的比例 | 67% | — |
| 最差 | 982 s | — |

典型样本：「嗯。」20 s；「你随便说」136 s；「含饮料，花费七块二」66 s；「修改一下：午饭是 26 不是 260」510 s。

根因（三层叠加）：
1. **一句简单话跑 5～7 轮模型**：记 7.2 元外卖的轨迹是 技能查找 → 读工具说明 → 读业务模块 → 查列表 → 写入 → 回读核验，每轮都让 DeepSeek 4.1 Flash 先推理一遍（p50 143 个推理 token）。
2. **OpenCode 通道慢且不稳**：Magpie 48 小时内 Hermes 发了 3504 次请求，101 次失败，其中 90 次是 `opencode.ai/zen` 的 502 EOF；重试把个别对话拖到 4～16 分钟。同样的模型走火山实测快一倍且无错误，但火山 Agent Plan 周额度已用完（Eddie 今晚确认），所以**通道暂时动不了**。
3. **语音记账没走快通道**：ASR 出来的「七块二」能解析，但「饮料」不在分类词表里，整句被交回了模型。

### 1.2 主动性（Hark Pro 对标项）

| 项 | 实测 |
|---|---|
| 7 天内主动消息 | **0 条**（`personal-conversation.sqlite` 里没有任何 cron/briefing 来源的 assistant 消息） |
| Heartbeat | 每小时跑，`effect=none`，digest 永远是同两条旧任务 |
| 「个人观察」cron | 每 30 分钟跑，两天产出 12 条 prepared，几乎全部来自编程会话，不是生活信号 |
| 推送 | `notifications.sqlite` devices=0、outbox=0。免费 Apple 账号没有 APNs 权限，App 里也没启用 aps-environment |
| 信息源 | 已连：账本、GitHub、Google 日历、Apple 日历。**断的：Gmail、工作邮箱、Garmin**；手机日历/健康只在 App 前台时可用 |
| Android 通知巡检 | 562 条信号，前几十条全是 milink / 传送门 这类系统噪音 |
| Hermes 后台消耗 | 每小时 60～114 次模型调用，用户没说话也在烧 |

所以「晨报没来」不是 bug 点，是整条链路没有一个环节能把东西送到锁屏。

### 1.3 iOS 客户端（源码审计，文件:行）

1. `ComApp.swift:15` 把 `.inactive` 当后台：下拉控制中心、来一条通知横幅都会断掉 SSE/WS/轮询，回来再全量重建。
2. `AppModel.swift:189-195` 回前台先串行拉完所有页面再开 SSE，这段时间舞台显示离线、新消息收不到。
3. `AppModel.swift:198-203` 每 15 秒整份重拉当前页；聊天页明明有 SSE 还再下载整份对话。
4. `AppModel.swift:18-20, 215-216` `datasets/fetchedAt/errors` 整个字典被观察，数据没变也写新时间戳，所有页面跟着重算。
5. `ScrollFrameMonitor` 正式包也在跑，滚动时申请 80 Hz 下限并写性能文件。
6. `ChatView.swift:38` 聊天列表不是懒加载，每条消息重新解析 Markdown；`AppModel.swift:278` 每条 SSE 在主线程解码；`UtilityViews.swift:13` 设置页每次解密全部 operation 文件且从不清理。

### 1.4 Codex 没按意向做的（会话原话核对）

- 「每天到固定点整合信息，给我行动建议、目标建议」→ 做了晨报/晚报配置，但**从未送达**（上面 1.2）。
- 「100 个字能说清就别用 500 字」→ Codex 只表态「会改规则」，没有收尾核验。
- 「不要跳转正在运行的程序，覆盖上来说完缩回去」→ iOS 平台做不到，Codex 说明了，Eddie 接受保留光效面板。
- 「这个 report 里的内容没有全部落实，比如动画」→ 802 补了舞台，但最后两回合被中断，Eddie 没确认。
- 2026100802 在手机上**打不开**（手机代理 127.0.0.1:1082 导致 Apple ppq 验证 TLS 失败），会话里没有修复记录。
- 免费描述文件 **10-13 到期**，续签脚本没写。

## 2. 产品判断

Hark Pro 值得抄的只有一个机制：**「事项卡 = 一个动作 + 一次点击」**，而且卡片是它先从邮件/日历里发现的，不是你问出来的。Muse 值得抄的是**只有一条对话、页面上没有第二个重心**。

Com! 的差异化不是再做一个通用助理，而是它已经拿到 Eddie 的账本、两份日历、两台机器的编程会话、微信群（Android 侧）。这些源 Hark 拿不到。所以路线是：**把已有的源做成事项卡，送到锁屏；别再加新面。**

## 3. 功能取舍

| 决定 | 内容 | 理由 |
|---|---|---|
| **修到底** | 主对话延迟（目标：简单话 < 5 s，记账 < 1 s） | 快是前提，不快一切主动性都像迟到 |
| **修到底** | 回前台不重连、SSE 优先、按需刷新 | 「网页感」的真正来源 |
| **做成** | 事项中心：日历冲突/待回邮件/账本异常/会话里未完成承诺 → 一张卡一个动作 | Hark 的核心，且源已经在手里 |
| **做成** | 锁屏送达：Bark 推送（免费账号可用）+ 今天页做收件箱 | 没有送达就没有主动性 |
| **做成** | 补齐源：Gmail、工作邮箱 | 没有邮件的「主动助理」只剩日历 |
| **合并** | 5 个 tab → 3 个：对话 / 今天 / 任务。记忆改成搜索入口，工作看板并入任务 | Muse 的简洁靠减重心，不靠换皮 |
| **冻结** | 工作舞台动画、白蓝双角色、锁屏数量小组件 | 能用就留着，不再投入；小组件受签名限制只能显示计数 |
| **冻结** | 雷鸟眼镜、Turbo-IO、SwiftTerm 终端页 | 与日常使用无关，且每个都占免费账号 3 个自签名额之一 |
| **砍掉** | Android 通知巡检里的系统噪音信号；Heartbeat 每小时空转 | 没产出还烧模型额度 |
| **砍掉** | 后台 cron 的「个人观察」从编程会话里挖建议 | 产出的是工程待办，不是生活行动建议 |

## 4. 路线

**P0 · 本周（本轮已做一半，见 §5）**
1. 对话延迟：短应答不推理、一般对话低推理、语音记账补词表走快通道。
2. iOS 连接与刷新：`.inactive` 不断线、SSE 先开、聊天页不重复拉快照、数据没变不重算、正式包关掉滚动采样。
3. 送达：后端 Bark 通道（已写好），Eddie 装 Bark 填 key 即通。
4. 装机：手机连 MBP 重签（10-13 过期前），并把手机代理对 `ppq.apple.com` 直连。

**P1 · 两周内**
1. 事项中心 v1：四个源（两份日历、账本、Gmail/工作邮箱）→ `matters` 表 → 今天页卡片 + Bark 推送；每张卡只有一个主动作（回复草稿 / 改日程 / 标记已处理）。
2. 晨报改成「今天最多三张卡」，没有卡就一句话，不生成空报告。
3. 后台模型预算：Heartbeat 改为事件触发；「个人观察」只在有新生活信号时跑。

**P2 · 之后**
1. 3 tab 改版（对话 / 今天 / 任务）。
2. 聊天列表懒加载 + Markdown 解析缓存；设置页 operation 文件清理。
3. 反馈学习：对事项卡「不想看这类」直接降权。
