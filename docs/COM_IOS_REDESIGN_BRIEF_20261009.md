## 可直接粘贴的 Prompt

你是一名资深 iOS 产品设计师。请为我的个人 AI 助理 App「Com!」做一次**全 App 页面重设计**，输出三个视觉方向的高保真原型。先读完下面全部背景，再动手。

### 1. 产品是什么

Com! 是我一个人用的私人 Agent 客户端（iPhone 17 Pro，iOS 26，SwiftUI 原生实现）。后端跑在我家里的 Mac mini 上，接入了我的账本、Apple 日历、Google 日历、Gmail、工作邮箱、微信工作群（经安卓手机的通知监听）、两台电脑上的编程会话（Pi / Codex / Claude Code）。它能直接执行：记账、建日历、设提醒、收藏链接、回邮件草稿、把编程任务派给电脑上的 agent 并跟进。

我对它的定位：**它应该一直记挂着我在意的事，提前发现问题，把信息整理好，准备好下一步，在合适的时机来找我，并跟进到结果。** 成功的感受是「我不打开它，它也在替我盯着；它来找我时，总带着一点已经准备好的东西」。

对标两款产品，各取一半：
- **Hark Pro**（2026-10 发布的主动式个人 AI）：它读邮件和日历，主动推「一张卡一个动作」，一次点击就办完。我要它的**主动性和行动卡机制**。
- **Meta Muse**：一条持续对话，界面极简，没有第二个重心。我要它的**简洁和一条流的体验**。

### 2. 用户（我）的底层需求，按优先级

1. **它先找我。** 一天里最想赢的时刻是：锁屏或首页出现一张它准备好的卡——「明天 10 点和 X 的会没订会议室，我订了 3 楼 B，好吗」「这封邮件要回，草稿在这」「本月餐饮超了 40%」。我点一下就处理掉。
2. **多说，但要好划掉。** 我选择「尽量多说」：有一点变化就告诉我，我自己划掉。所以流里会有很多它发起的条目，设计必须让「扫一眼、划掉、批量处理」极其顺手，不能让多说变成噪音。
3. **一条流。** 它发的卡、我说的话、它的回复，按时间排在同一条时间线里，像和一个会主动开口的人聊天。待处理的卡在顶部有一个收起的汇总条。
4. **卡片按类型混合**：
   - 可自动完成的 → **一句判断 + 一个主按钮**（次要入口「改」）；
   - 要我表态的（回邮件、回群消息）→ **摘要 + 它写好的草稿**，我改完发；
   - 复杂的 → 卡片只是入口，点进去在对话里聊完。
5. **状态要真实。** 「收到」不能画成「做完」；它正在做、做到哪步、要不要我批准，都要能看到。
6. **信源断了要知道**：它在流里发一张卡（「我读不到 Gmail 了，点这里重新授权」），同时顶栏舞台里的角色举个牌子。平时界面上不显示任何连接状态列表。

### 3. 信息架构（已定，不要改）

底栏三个 tab，用 iOS 26 的 Liquid Glass 悬浮胶囊 Dock：

**① 流（主页）**
- 顶栏 = **工作舞台**（见 §4）。
- 舞台下方：一条可收起的「待处理」汇总条（N 张卡等我决定，点开展开成列表，可批量划掉）。
- 主体：时间线。元素类型：它发起的事项卡（三种形态见 §2.4）、我的消息气泡、它的回复（去气泡、有排版层级：标题/要点/引用）、系统卡（信源断了、任务完成回执）、月度账本卡（点开是简单列表）。
- 底部：**保持现在的输入框布局**——文本输入框为主，右侧一个麦克风按钮，录音时输入区变成光晕波形（voice-glow 那种）。这块不要重新发明。
- 要画的状态：空流（第一次打开 / 今天还没有事）、早上有 5 张待处理卡、对话进行中（它正在调用工具）、它刚推了一张「信源断了」卡。

**② 在办**
- 三组：等我决定（审批卡，warning 描边置顶）、正在跑（哪台机器、哪个 agent、到哪一步、预计多久）、目标进展（1～3 个真实目标，每个一行进度）。
- 任务详情页：状态头部 → 我要做的决定 → 步骤时间线 → 成果与证据。

**③ 工作**
- 第一屏是**双机项目看板**：每个项目一张卡（最近在干什么、哪台机器、哪个 agent、下一步建议、未收尾的事），按最近活跃排序。
- 点进项目 → 该项目下的会话列表和「派新活」入口；会话详情沿用流的对话表面。
- 「新建工作」是右上角主按钮。

**头像菜单（顶栏左侧角色头像点开）**：记忆（搜索 + 分类 + 纠正，保留完整页）、账本、连接器、设置。

**明确不画**：终端页、锁屏/桌面小组件、独立的「今天」页、独立的「记忆」tab。

### 4. 角色与工作舞台（我最在意的个性部分）

Com! 有两个伙伴形象（附图：白脸 + 戴蓝贝雷帽的蓝脸，双脸也是 App 图标）。我要的是：

- 舞台**固定在顶栏的位置**（原来放状态/标题的那一条），高度约 120～160 pt，可下拉展开到约 240 pt，可上滑收成一条细状态。
- 角色在舞台里**生动活泼地干活**：有一张小桌子/工作台，它读邮件时翻信、查日历时翻本子、派活给电脑时把纸飞机扔出去、等我批准时举牌子、空闲时趴着打盹、信源断了举「邮箱断了」的牌子。
- 角色旁边有**小对话框**，一句话说它正在干嘛（「在看你早上的 6 封邮件」「正在等 Codex 跑完」）。
- 动作由真实事件驱动，不是装饰循环；减少动态效果时静止。
- 这不是当前那版「电脑 + 转椅 + 虚线路径」的复刻，请重新设计舞台的空间和动作词汇，给出 8 个状态的关键帧：空闲、读取信源、思考、执行工具、派活到电脑、等我批准、交付完成、信源断了。

### 5. 交互与动效规则

- 卡片手势：左划=划掉（不感兴趣，之后学习降权），右划=主动作，长按=「和它聊这件事」。
- 「尽量多说」的代价由设计吃掉：同类事项自动折叠成一张（「3 封邮件待回」），展开才逐条。
- 每屏一个焦点；文字层级最多四级（20 / 16 / 15 / 13）。
- Liquid Glass 只用于悬浮控件（顶栏、Dock、回到最新胶囊），内容保持不透明。
- 它的回复短：100 字能说清不用 500 字。设计上给短回复留好版式，不要为长文优化。
- 动效：发送气泡飞入、新卡从舞台「递」下来、划掉时卡片折叠消失；全部 ≤ 400 ms，弹簧阻尼 0.85 左右；支持 ProMotion。
- 全部文案中文，日期格式「10月9日 周四」，金额「¥1,234」。

### 6. 视觉：请出三个方向，每个方向独立成套

- **方向 A · 亮色原生**：白/浅灰表面、系统字体、一种强调色；像 Apple 自家 App，白天通勤看得清。
- **方向 B · 深色氛围**：深底柔光、大圆角卡、环境感背景（参考 MercuryOS 私人 agent 的「安静的私人空间」），角色在舞台里是发光的。
- **方向 C · 纸感便签**：暖白纸底、衬线或窄字标题、卡片像便签、强调「它帮我写好了」的被动感（Hark 的方向）。

三个方向共用同一套信息架构和组件清单，只换视觉语言。每个方向都要给：色板（浅/深各一套 token）、字阶、圆角与间距、组件（卡片三形态、审批卡、项目卡、输入区、Dock、舞台）。

### 7. 交付物

1. 每个方向 **7 个关键屏**的高保真原型（iPhone 17 Pro 尺寸 402×874 pt）：流·空态、流·早上 5 张卡、流·对话中、在办、任务详情、工作·项目看板、头像菜单。
2. 工作舞台 8 个状态关键帧（每个方向一套）。
3. 一页「为什么这样设计」：每个方向一段，说明它怎么服务 §2 的六条需求。
4. 组件与 token 清单，以 SwiftUI 可直接实现为前提（我现有 `DesignSystem.swift` 的 token 命名：background / surface / elevated / fill / separator / textPrimary…/ accent / coral / ink，沿用这些名字）。

### 8. 禁区

- 不要把它做成通用聊天机器人界面；流里主角是**它主动发的东西**，不是我的输入框。
- 不要画任何「仪表盘」「数据大屏」。
- 不要改输入区布局。
- 不要用渐变堆砌、emoji 当图标、通用模板感。
- 角色不许在首屏居中待机占满屏幕；它住在顶栏舞台里。
- 所有状态文案要能对应真实后端状态（等待批准 / 执行中 / 已送达 / 结果未知 / 已完成），不要发明「已完成」的假状态。
