# Com! 产品方向 · 2026-10-01

> 2026-10-01 最新实现以 [Com! 1.3.1](com-1.3.1.md) 为准：Codex 改为蓝色毛绒；小窗固定 Pi、录音结束直接发送，无文字审阅，并支持上滑展开。以下保留早期规划，未列入 1.3.1 实现记录的项目不代表已交付。

Com! 是手机上随时唤起 Pi 与 Codex 的共同工作入口。它沿用会话工作台现有的真实会话、只读历史、审批与终端能力，逐步接管「随行」的快捷语音输入。显示名已改为 Com!，包名保持 `work.eddie.sessions`，原配对和缓存可以随安装升级保留。

## 两位伙伴

两位角色属于同一套流体圆脸家族：柔和的立体材质、可读的胶囊眼、留出表情和动作空间。区别由**轮廓、眼部动作、材质、配色**共同承担，不能只换色或贴上文字。角色名称始终作为无障碍名称和小尺寸辅助标识。

| | Pi | Codex |
|---|---|---|
| 性格 | 亲近、灵活、善于接住零散想法 | 专注、精确、推进复杂工作 |
| 造型 | 略偏水滴的柔圆轮廓，暖白珠光，柔软的下颌形变 | 稍更凝聚的圆脸，银灰陶瓷光泽，清楚的边缘高光 |
| 五官 | 略宽的圆角眼，视线转向幅度稍大，轻微不对称 | 窄一些的胶囊眼，注视停顿更稳，眨眼更短 |
| 识别细节 | 左侧一枚淡青绿的小浮点／弧线 | 右侧一枚雾蓝的细弧／切面高光 |
| 节奏 | 呼吸与倾听有柔和弹性 | 思考时动作更集中、停顿更明确 |

现有 Grok 灵动助手 v2 是动作和互动基础，不能直接当成已经完成的双角色。需要分别产出可编辑的两套动画资产及静态缩略图，再把当前 `BotAvatar(state)` 扩为 `BotAvatar(agent, state)`。首页用完整动画，会话标题只放一个小头像，列表卡使用静态帧以控制内存。互动后恢复真实业务状态；只在实时观察到完成时短暂庆祝，离线缓存、只读历史不会假庆祝。

## 页面与导航

| 入口 | 页面与作用 | 主要操作 |
|---|---|---|
| 打开应用 | **伙伴首页**：Com! 标识、Pi／Codex 切换、伙伴、最需要回应的会话、统一输入框 | 继续、输入、语音、开空会话 |
| 首页／导航 | **工作中**：跨 Pi／Codex 汇总运行中、待回应、失败 | 待回应与失败置前，直接进入正确会话 |
| 首页／导航 | **全部会话**：保留 Agent、目录、日期、归档与全文搜索 | 打开历史、查找、筛选；历史默认只读 |
| 会话 | **对话详情**：消息、过程分组、审批、输入、会话内搜索 | 继续当前会话；终端留在本页的二级切换 |
| 系统长按／应用麦克风 | **快捷语音卡**：底部轻窗，不离开当前应用；显示伙伴、目标会话、录音与识别结果 | 开始／取消、改字、切目标、发送；失败可重试 |
| 右上角／导航 | **设置**：分组页面而非一个长弹窗 | 配对、快捷入口、默认值、通知、外观、数据管理 |

会话、审批、搜索和终端均沿用现有真实数据语义。主页只呈现当前 Agent 最相关的一个会话，工作中页负责跨 Agent 排序，避免在两个首页各复制完整历史。语音卡既可新建会话，也可向明确选定的当前会话补充；发送前必须显示目标名称。

## 语音的完整路径

1. 用户从系统长按、应用内麦克风、桌面快捷方式或快捷磁贴打开同一个语音卡。系统长按使用 Android 助手入口的透明 Activity；「小窗」是 Activity 内的底部卡，不依赖悬浮窗权限。
2. 先确定 **Pi／Codex** 和 **新会话／某个现有可输入会话**。默认沿用用户设置的伙伴，当前会话入口默认回到该会话；两者都要在卡片顶部可见。
3. 前台录音时伙伴进入 `listening`，显示声量反馈与可取消的录音计时。静音、最长录音、被打断与权限拒绝均有清楚反馈。录音完成后本机保存原音与稳定请求 ID，再加入可靠上传队列。
4. Mac mini 转写返回可编辑文字。默认先落入草稿；如果用户明确开启「默认目标自动发送」，才允许安静停顿后倒计时发送，并保留取消窗口。没有明确目标时必须停在草稿。
5. 发送按目标走会话工作台现有的创建／输入语义，后端按请求 ID 防重复；成功回到正确会话，失败保留录音、文字和重试入口。

旧「随行」的 `/api/v1/voice` 只通向 Pi，使用独立凭据与任务记录，不能直接当 Com! 的双角色语音后端。Com! 需要自己的音频受理与转写接口，可复用 Mac mini 已有的本地 ASR 服务，但必须先核验其在线和转写效果。迁移期间两个应用并行：先验证 Com! 的真机录音、断网重试、Pi/Codex 去向及内外屏小窗，再在 HyperOS 中切换默认助手。核对「随行」待上传录音与历史后才考虑停用；目前不修改系统默认助手、不卸载「随行」。

## 设置页

| 分组 | 内容 |
|---|---|
| 连接 | Mac mini 状态、地址、配对、更换服务、上次同步时间 |
| 语音与快捷呼出 | 麦克风权限、默认助手状态、试用快捷窗口、默认伙伴与目标、自动发送开关、录音与重试记录 |
| 伙伴 | 默认打开 Pi／Codex、各自的语音/动画预览、每位伙伴的最近会话 |
| 通知 | 运行完成、失败、待回应分别开关；点通知进入对应会话 |
| 外观与动效 | 系统／浅色／深色、字号、完整／轻量／减少动画；尊重系统减少动态效果 |
| 数据与安全 | 缓存占用、清除缓存、离线记录说明、凭据状态、语音记录保留与删除 |

## 动效语言

| 状态 | 表达 | 边界 |
|---|---|---|
| 待机 | 低幅度呼吸、视线轻跟随 | 页面离屏暂停，省电模式可用静帧 |
| 倾听 | 眼睛看向用户、声量驱动轻微形变 | 真正开始录音后才出现，不用循环假波形 |
| 转写 | 短暂停顿与浅色环流 | 录音已结束；不能误表示已提交 |
| 思考／执行 | 连续、克制的环流和视线收束 | 只根据实时会话状态 |
| 待回应 | 暂停在可读表情，呼吸变慢 | 审批与待回应按钮始终可见 |
| 完成 | 1.5–2 秒的短庆祝后回待机 | 仅本次状态转移触发一次 |
| 错误 | 轮廓收紧，状态标记与文字同时出现 | 不用红色闪烁；轻点互动不覆盖错误 |

切换 Pi/Codex 时两个角色保持视线连续，主体约 240–320 毫秒淡入与位移；卡片和面板用已有 Compose 弹簧动效。语音卡出现快、收起稳，不做全屏炫光。系统减少动态效果时保留状态静帧、文字和触觉反馈。

## 折叠屏

外屏使用单列首页、底部语音卡和抽屉式历史；内屏根据**实际可用宽度**安排伙伴与工作卡，必要时使用窄导航轨道。只有会话列表和正文都足够宽时才固定双栏；选择会话或点击正文后侧栏可收起。语音卡在内屏保持有上限的宽度，避免铺满屏。验收时分别检查内屏、外屏、键盘弹出、旋转与小窗遮挡。

## 实施顺序与验收

1. **产品壳**：显示名、双角色可编辑资产、首页和设置分组；验证真实会话、只读历史、终端与审批不回退。
2. **应用内语音**：录音、转写、草稿、两位伙伴的去向、失败重试与防重复；先在普通 App 内跑通。
3. **系统快捷入口**：透明语音 Activity 与助手注册；内外屏和长按实测后再切换默认助手。并行保留随行直到旧数据核清。

当前 Android 1.2.0 仅完成显示名 Com! 和上一版「灵动伙伴」界面／单套 Bot 的实机安装。以上双角色与语音功能是后续实现规格，不能将规划误称为已装机功能。
