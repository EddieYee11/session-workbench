# B3 提醒卡与承诺设计

实现范围：复用 Mac mini ~/.pi-gateway/state/reminders.json，原 remind 扩展继续创建，Com 只对已有真实 ID 做动作。对话流按 tool.completed 的 remind result.details.id 关联，今天页列待提醒；不靠文本猜测 ID，不创建第二套提醒数据库。

确认→done；取消→cancelled；推迟→max(原 due,当前时间)+10/60 分钟。每次携带持久 request_id 与 due/status 快照；同请求重试返回同结果，快照过期拒绝；客户端超时不自动重放，必须回读核实。网络/来源不可用禁用按钮并显示错误。

既有网关和扩展也写这个 JSON。已增加共同 .com-lock 与基线比较写入：网关投递后仅更新该条，并保护投递过程中用户的新取消/推迟，扩展按变更合入最新文件。不动 settings、不加入新扩展、不升级 Pi。动作改变记录，不能撤回已经发出的微信；若在到点投递期间取消，原投递可能已经开始，最新取消仍保留。Com 动作回读证明记录变化，不证明此前消息被撤回。

真源在 mini ~/pi-hermes，不修改 MBP 只读镜像。网关变更单独提交76c7652，生产只拷贝两个原文件和新共享存储 helper；修改前留 .before-com-b3 文件。源哈希基线固定，漂移时部署补丁拒绝执行。Com 保存 gateway_integration 适配来源供审查。

真实验证使用原已安装 remind 工具创建4条明确标注验收、2099年到期的临时记录，不调用模型、不发送消息。四动作及 stale 拒绝经 API 回读后，测试记录删除；具体结果见 B 交付报告。它们不进入任务台账或主对话。

## 承诺追踪：只设计，等用户选择

| 方案 | 收益与成本 | 对 task 真源的影响 |
|---|---|---|
| 复用 goals | 沿现有 goal/events、批准入口；需区分目标与到期承诺，定义履约证据与取消 | goal 是意图，执行仍必须引用既有 task ID；不能以 goal.done 推断 task 验收；定时调度当前仍关闭 |
| 独立轻量 promise 实体 | 更明确 person/text/due/source/status/evidence，适合“答应了谁”；需新增持久实体、迁移及产品页 | promise 不承担执行/送达台账；履约必须指向实际来源与 task/event，不能形成另一任务状态机 |

本轮均未实现。建议先确认个人承诺是否与目标共页、是否需要人员/兑现证据，再选择实体；不能用提醒已触发当作承诺已完成。
