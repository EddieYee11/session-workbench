# 两份报告的现场核对与更新 · 2026-10-08

基线为 `2158602`；核对对象为本仓库源码和 Mac mini 的实际 Hermes 主线，不切换到 Pi 或另起后端。输入资料为用户提供的上下文优化清单及 `report.md`；报告中的待选架构、模型价格、外部产品结论不视为现场事实。

## 已落实

- **记忆继续按需读取**：基线已经取消 `stream_chat` 的全量 MemoryCatalog 注入和前置 Hindsight HTTP。保留每轮零自动记忆调用，不重新加入 25 条记忆索引。需要时使用 `memory_recall` 或 `context_read`，Markdown 仍是唯一写入权威。删除遗留但未调用的 `slim_facts/slim_memories`，避免代码注释误导诊断。
- **工具来源由运行时填写**：模型可见 schema 不再包含三个 `origin_*` 参数。原始来源先写入 `hermes-runs.sqlite/tool_sources`，Hermes 原生 `pre_tool_call` 按实际会话和在途运行补齐；后台事件/worker 保留自己的已授权来源。歧义、缺失和冲突明确拒绝。底层 FastMCP 仍验证来源参数，插件缺失时不能执行写入，不靠“最近一条用户消息”兜底。
- **说明按需加载**：长业务参数表移入 `context_modules/business.md`。保留原生 `tool_search/describe/call` 和 65 个延迟加载的核心工具，真实探针首轮只有 8 个 eager 工具。34 个 Com 工具的完整公开 schema 从 33,330 降为 24,900 UTF-8 字节，减少 25.3%；这不等于每轮 token 降幅。
- **固定前缀与计量**：稳定 system 契约在前，排序后的当轮上下文在后；模型上下文不再重复携带三个工具来源 ID。源身份仍完整保存在服务端。组装记录分出 system/context/history/memory 字符及字节；原生请求记录 schema 字节、哈希、实际 prompt tokens、缓存读取量和命中比例。日志不记录提示词、参数或凭据，指标文件已有 8 MB 轮转。
- **持久性**：主会话、任务和 Hermes 运行库启用 WAL；现场三库均读回 `wal`。继续使用已有 SQLite 收据、幂等和后台任务，不迁移 Postgres。
- **审批**：新提案有效期改为 30 分钟，列表将过期提案投影为 expired，批准接口拒绝过期请求；历史提案沿原有效期。读取不改写原记录。iOS 在决定前展示实际对象、收件人、金额、路径等可用字段，并可展开全部原始参数。既有明确授权继续沿用，不额外制造确认步骤。
- **双端文案**：后端下发 `work_events[].display_text`，iOS/Android 优先采用；工具结束只说“这一步结束/已有回执”，不会伪装成整件事已经验证完成。iOS 原始记录保留在折叠详情中。
- **iOS 状态区**：聊天顶部可展开的白蓝脸状态区，共用真实的思考、处理、待确认、回复、异常和连接状态。默认收起，空闲没有渲染循环；动画仅随状态变化，减少动态效果、低电量和后台降为静态。沿用已有 SSE snapshot/update，不凭空要求后端发送未实现的事件类型。顶部原有头像停止空闲持续刷新。
- **部署兼容**：Hermes 准备脚本安装来源绑定插件并保留已有模型选择；Com 安装脚本设置启动节流。此次运行模型仍为现有 Magpie/DeepSeek Flash，未更换账户或权限。

## 验证证据与边界

本轮后端 529 项回归、Swift Core 4 项、iOS Release 构建、Android Kotlin 编译及五条关键 iOS UI 路径通过。模拟器覆盖：状态区展开收起、阅读历史时新回复不拉动位置、长 Markdown 返回最新、语音自动发一次、取消后不发送迟到转写。截图经实际查看。

Mac mini 的真实隔离探针验证了按需模块读取及完整的 `tool_describe → business_operation(remind/list)` 链路，模型未传来源 ID，native tool 完成记录 `error=false`。只做读取，没有创建/取消提醒，没有向主聊天添加测试用户消息。

轻对话探针约 5.5k prompt tokens、首字约 1.77 秒、自动记忆调用 0；模块读取探针经过多次工具往返，首字约 9 秒。这些是特定测试样本，不是手机端 SLA 或总体加速倍数。缓存有真实命中，但同一会话跨轮仍出现 0 命中；已记录计量，不宣称稳定命中或承诺省 50–70%。

iOS 发布构建号为 **2026100801**，已覆盖安装到已连接 iPhone 并读取构建号；首轮启动成功，最终审批展示补丁覆盖安装后，远程打开被设备锁屏拦截。解锁后可直接打开。模拟器通过不代表已经测得真机持续 120 FPS；手持滚动体验与系统调度仍需正常使用观察。

## 报告中不直接套用的部分

当前 HTTPS、真实 launchd 服务、MCP 和后台调度已经存在；两台机器均未发现报告指向的独立 `~/workspace/personal-agent` 骨架。没有降低 TLS 要求，没有创建第二套 API。

Postgres/openmuse 迁移、AG-UI 换协议、Bark、付费开发者账户、锁屏小组件、每周记忆整理和便宜模型历史摘要均是后续独立需求，本次未实施。现有原始历史完整保留，近轮 14 KB/8 条裁剪及按 ID 回读继续工作。应用关闭后的通知仍受现有 APNs/系统后台刷新条件限制，不能把前台 SSE 当成已验证的锁屏推送。没有新增 launchd 日志轮转守护进程。

## 部署与回滚

先由 Syncthing 同步源码并核对哈希，再在 mini 上运行 `backend/optimize_hermes_profile.py` 更新插件；其空闲检查和自动备份必须通过。随后在无主聊天/worker/原生 lease 的情况下刷新 `ai.hermes.com-personal` 和 `work.eddie.sessions`。模型可见 schema 与来源绑定插件需要成套更新。

回滚时同时恢复匹配的代码和 profile 插件/config 备份；勿只移除插件而保留隐藏来源参数的新 schema。WAL 和新增来源表兼容旧数据库内容，不删除对话、任务或记忆。
