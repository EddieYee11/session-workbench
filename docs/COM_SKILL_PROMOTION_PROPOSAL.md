# B5 技能草稿晋升提案（未实施）

当前 .agents/skills 为技能真源（workspace.index.md）；Pi 生产发现 ~/.pi-gateway/skills。两者不是自动同步关系。本阶段没有创建草稿目录、修改技能、增加 Pi 包或启用自动晋升。

建议暂存区：AI_Work_System/agent-kit/skill-drafts/<proposal-id>/，沿既有 Agent 控制面，不另建根目录。内容包括 SKILL.md、来源/许可、目标真源、base Git hash、补丁、风险与评测记录；草稿不加入生产 skills 搜索路径。

流程：提议 → 检查 SKILL/frontmatter/引用路径合法、单文件≤15KB、无路径逃逸、补丁可在明确基线应用 → 只在临时副本应用 → 至少一次真实低风险样例评测并保存输入/预期/实际结果 → 今天页「仅供知情」提供只读草稿待审入口 → 用户进入差异页点击明确确认 → 原子合入、留 Git 提交、回读技能与发现状态。失败、基线变化或评测缺失不得晋升；Git 提交失败也不能声称完成。

每次晋升保存基线、单独提交及旧文件；回滚用该提交的反向补丁，先验证当前基线避免覆盖用户后续修改。目录、评测分数和风险词匹配只是审查辅助，不足以证明安全。

Com Agent 具有完整权限，暂存区是约定与评审流程，不是访问控制。完整权限的 Agent 仍能绕过目录约定；默认绝不自动晋升。实施前需确认：暂存路径、低风险评测清单、确认页及 Git 回滚方式。上述 UI 为建议，未实现。
