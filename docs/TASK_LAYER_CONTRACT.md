# 任务层后端契约（Mac mini 侧）

目标：把“手机端 Session 管理器”升级为“主助理 + 后台任务系统”。
用户只在主聊天里表达；系统负责识别任务、维护状态、分配独立执行上下文、把结果送回主对话。

客户端（`muse-refresh` 分支）已就绪：
`TaskLedger.kt` 按 `message_id` 对 runs 分组渲染任务；`WorkProposalSection` 为工作动态。
下面是 mini 侧需要验货和补齐的部分。**先验货，再按契约实现，不要按假设开写。**

## 一、验货清单（在 mini 本地执行）

1. Hermes 服务版本与配置：当前运行的是哪个版本，哪份配置。
2. `delegate_task`（创建独立上下文子 Agent）是否存在、是否可用。
3. 任务队列：文档提到的持久化 Kanban 任务队列是否真实启用；任务存在哪里（DB 表？文件？）。
4. 事件流：子 Agent 状态查询、会话管理、HTTP 运行接口与事件流，哪些已接通。
5. Pi：RPC 模式是否可用（新建会话 / 补充指令 / 中断）。
6. Codex：App Server 是否在运行（thread/start、turn/steer、turn/interrupt）。

验货方法：在 mini 本地直接检查服务与配置，不要只看文档；HTTP 接口用现有配对 token 经 Tailscale 调。

## 二、待新增的后端能力（按优先级）

### P0：父子关联（最小解锁动作）
- `GET /personal/work/proposals` 的 items 增加 `parent_message_id`（哪条主聊天消息派生的）。
- `GET /personal/conversation` 的 runs 增加 `parent_message_id`（如已有 `message_id` 则复用，无需改）。
- Pi/Codex 会话记录增加 `parent_message_id`。
- 客户端分组逻辑零改动即可升级：现在按 `message_id` 分组，字段到位后自动归位。

### P1：任务事件
- runs 的状态机事件结构化：created / started / tool_call / completed / failed，
  携带时间与摘要。客户端按任务 ID 分组展示时间线。
- 状态必须由真实执行驱动，不编造“正在努力分析”类文案。

### P2：给执行中任务补充指令
- `POST /personal/tasks/{id}/input`，body：`{text, request_id}`。
- 语义为 steer：排队，在下一次模型调用前送达；返回“已受理”而非“已完成”。
- 客户端任务详情页的输入框接这个接口（UI 已预留位置，接口到位即接）。

### P3：完成摘要回流
- Pi/Codex 任务完成（或失败）后，后端生成摘要，写入 Hermes 主对话一条消息：
  “任务 X 已完成：……（点进任务详情看完整记录）”。
- 这是“自动执行”信任闭环的另一半；没有它，派出去的任务会石沉大海。

### P4：规划器循环（最后做）
- 触发点：新消息到达、任务完成、任务阻塞、已授权计划到期、相关外部事件。
  没有新事件就等待，不持续扫描全量聊天记录。
- 职责：识别候选任务 → 创建/更新任务（经任务接口，有真实记录）→ 不自动获得执行权限。
- 第一版不需要独立的 Router/Planner/Supervisor 多 Agent，主 Agent + 受控任务接口即可。

## 三、权限分级（第一版边界）

| 对话中的意图 | 默认处理 |
|---|---|
| 明确交办（“帮我查 pnpm 为什么卡”） | 授权范围内创建并执行 |
| 补充要求（“不要动代理配置”） | 更新任务约束，不建新任务 |
| 表达困扰（“文件太乱了”） | 给建议，不直接动文件 |
| 长期愿望（“想做个个人网站”） | 可建目标草案，不自动无限开发 |
| 发送消息、购买、发布、删除 | 按具体权限规则确认（记账这类用户已明确授权的可自动） |

自动识别候选任务 ≠ 自动获得执行权限。

## 四、状态可信度要求

- “已受理”“执行中”“执行结束”“验收通过”是不同状态，不混用。
- 取消需确认实际停止后再显示；重连/重试要按 request_id 去重。
- 并发写代码任务先限并发，用独立工作副本或 git worktree；上下文隔离 ≠ 文件隔离。
- 动态状态（谁在运行、等什么批准、哪条指令未送达）放数据库，不只靠 Markdown 记忆。

## 五、验收标准（第一版）

1. 连续交办两件事 → 产生两项任务；给其中一项补限制 → 更新旧任务，不建第三项；闲聊不触发操作。
2. 后台执行时主聊天可继续聊；手机退出不终止 mini 任务；重开恢复状态。
3. 状态与控制可信：取消/重试/去重行为符合第四节。
