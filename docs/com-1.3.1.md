# Com! 1.3.1

这轮直接升级原 `work.eddie.sessions` 应用，保留配对、缓存、会话和终端。版本号 1.3.1 / 5。

## 布局与伙伴

- 首页以居中的大伙伴和主标题为视觉中心，保留 Pi / Codex 切换，只显示一条最相关会话，工作中和历史是次级入口。
- 对话页为居中角色、标题胶囊、两侧导航；输入框统一为一行胶囊，文字变多后可自然增高。Pi 和 Codex 的回复用各自的浅色气泡，历史仍只读，终端仍保留 ANSI 色彩。
- Pi 使用原流体圆脸，Codex 使用用户提供的蓝色毛绒原生 Canvas 组件。毛绒支持局部拉伸和回弹；去掉默认矩形点击波纹，保留自身触摸形变。
- 同一个角色与输入面板跨越首页、会话场景，角色从首页缩入标题。仅切换场景时做位置过渡；页面滚动时立即跟随位置，不拖尾。退出的页面屏蔽触摸和无障碍操作。
- Pi / Codex 常驻同一个旋转轴，以背靠背方式原地转身，侧面有短暂体积、轻微模糊与弹性落定，避免角色在画框边缘突然消失。两位伙伴共享留在地面的柔和悬浮阴影；Codex 状态点固定在头部坐标。选择色块弹簧滑动并短暂伸缩。遵循系统动画时长缩放。

## 电源键语音

- 使用 Android 系统助手入口，不依赖悬浮窗权限。小窗固定为 **Pi**。
- 新打开且没有待处理录音时开始前台录音。首次申请麦克风权限。检测到有效说话后静音约 0.5 秒自动提交；最长 60 秒，也可手动点“立即发送”，不停在转写审阅页。
- 原录音上传到 Com 的 `/voice/transcribe/{capture_id}`，由 Mac mini 已有的本地 ASR 转写，随后自动走原会话创建接口交给 Pi。转写只是内部步骤，不要求用户确认。
- 提交后由 WorkManager 继续处理，小窗持续等待并显示 Pi 的流式回复，回复后可继续录音到同一会话；关闭小窗不取消已提交任务。联网约束会在离线时排队。错误保留原录音，可重试或重录。
- 请求使用稳定的录音标识和发送回执，不用重试创建重复任务。只有收到 accepted 回执并保存可恢复的会话凭据后才删除本地录音。
- 上滑顶部把手或点右上角展开：卡片先拉大；录音中会先结束并提交，然后进入同一条 Pi 会话。上传中展开会在主界面显示进度，回执到达后打开相同 sid。
- 收起尚未提交的录音会保存为待发送内容，下一次可继续发送或重新说。不会静默提交被取消的内容。

- 新语音接口及既有 API 测试共 5 项通过：认证、格式与大小限制、失败重试、同录音缓存和标识冲突；转写接口本身不启动 Agent。
- Mac mini 已收到同哈希代码并重载现有会话服务；中文音频通过新增转写接口返回 200，返回文字可理解，但有一个字的识别偏差。

- 默认系统助手已从旧 `work.eddie.piquick` 切至 `work.eddie.sessions/.QuickVoiceActivity`；旧应用和数据仍保留。

- 已看到真实 `voice-` 请求的 accepted 回执，说明录音上传、转写、创建 Pi 会话链路已有实际成功记录。1.3.1 的 0.5 秒自动发送、小窗回复和展开至同一会话尚未完成实体使用验收。
