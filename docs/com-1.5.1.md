## 可使用的变化

- 主对话保留 Hermes。标题改成 76dp 紧凑布局与 98dp 渐变透明覆盖，消息滚动经过标题下方；不再把 128dp 独占为实白头部。用户气泡为浅绿，助理为浅灰。
- 用户 `avatar-crab.bundle` 的原生 Compose 像素螃蟹用于 Hermes：待命、倾听、思考、工具执行、回应、出错、离线，以及仅在明确成功时的一次欢呼。普通回复结束回到待命。系统关闭动画、后台或不可见时停止循环，无新增网络或 WebView 桥。
- Hermes 通过 `react_to_user_message` 实际选择一个表情，绑定当前用户回合。表情随消息持久保存、经过原 SSE 更新传到手机。仅新的前台直播事件触发系统轻触感；历史、重连、重复事件不重复震动。模型可不附表情，不用关键词伪造。
- 快捷语音和记账小窗都直接交办原生 Pi，继承已有 collect Skill 与 bookkeeping 等工具。持久受理后收窗，实际输出可在工作会话回看。受理回执不代表账本已经写入；记录实际工具结果，账本写入需后续 recent 回查匹配 ID、金额和已提供的分类/备注。
- 主消息页直接显示待授权卡；任务页顶部显示待授权队列，匹配任务详情也有「允许并启动 / 拒绝」。卡片列出任务、执行器、目录、权限和原因，并可展开完整指令。两处操作同一 proposal ID，处理结果同步显示。原生执行器临时审批在对应任务详情读取该 session 的审批项，沿用执行会话的原审批接口。
- 有效待授权建议在服务端排序置顶，避免被新历史记录挤出；离线授权控件禁用。

## 投递与生命周期

`POST /personal/quick-voice/messages` 持久受理，`GET /personal/quick-voice/receipts/{request_id}` 核对后续进度。同请求号、同内容去重，不同内容冲突；未确认的发送与重启后 starting/sending 归 unknown，不自动重放。旧 Hermes 已受理的同请求也不会升级后再次交 Pi。

每条语音拥有独立 Pi 会话，确认 completed、静置两秒、原生事件未变化且无人附着时回收专属 pane，保留原生历史。工作页继续输入、连接终端或新的原生活动撤销自动回收。失败和未知状态保留供核对。

Hermes 表情使用当前回合的一次性能力，拒绝历史、助理回复、通知回执、错误或过期 token；每轮最多一个表情，同表情重复调用幂等。
